## 1. 模块划分（crate 级）

**C1 · crate 切分线画在"信任边界"，不画在"分层边界"**

原方案的 6 个内核 crate（`core`/`infrastructure`/`domain`/`application`/`runtime`/`interfaces`）**合并为 1 个 `kernel` 单体 crate**，内部用 `mod` 隔离、`pub(crate)` 控制可见性。分层从"编译期强制"降级为"`xtask layering` lint 强制"。

**为什么合并**：不是为了少写 `Cargo.toml`，而是因为**由 AI 主体实施时，跨 crate 抽象边界是最大的一致性风险源**——单 crate 内编译器能给出精确报错位置，跨 crate 时 AI 会在 trait 可见性、孤儿规则、循环依赖上反复打转。同时单 crate 大幅降低上下文窗口压力。

| crate | 时空层级 | 职责 | 允许依赖 | 禁止依赖 |
|---|---|---|---|---|
| **`core`**（独立，纯类型） | 数据规范（规则基座） | ID / 版本 / 能力 / 事件 / 错误码 / 状态枚举 / 配置 / 清单类型 | serde、thiserror、schemars 等基础库 | **任何本项目 crate** |
| **`sdk`**（独立，L3） | 插件侧绑定 | `HostApi`、`trait Plugin`、`#[plugin]` 宏、`Migratable` | `core` | `kernel`（硬禁） |
| **`kernel`**（单体） | 全部内核层级 | `mod core_bridge` / `mod infrastructure` / `mod domain` / `mod application` / `mod runtime` / `mod interfaces` | 全部外部库 + `core` + `sdk` | ——（`runtime` 只做启动/停止/回收，不写业务流转） |
| `plugins/*` | 能力单元 | 仅示例：LLM 适配器、工具注册 | **`sdk` 唯一** | `kernel`（硬禁，CI 扫描 `Cargo.toml`） |

**为什么必须是 3 个 crate 而不是 2 个**：依赖方向是 `kernel → sdk → core` 的单向链。若把 `core` 并进 `kernel`，就会出现 `sdk → kernel`（要用 `Envelope` 等类型）与 `kernel → sdk`（要调 `trait Plugin`）的**循环依赖**，Cargo 直接拒绝。故 `core`（纯数据类型、体量极小、几乎不产生上下文负担）必须独立。

**代价与补偿**：合并后失去编译期的分层强制（不变量 I5）。补偿手段：

- `xtask layering`：静态扫描 `mod` 间的 `use` 路径，禁止 `domain::*` 引用 `infrastructure::*` 具体类型等越界引用；
- `xtask deps`：扫描 `plugins/*/Cargo.toml`，出现 `kernel` 即失败（这条是**信任边界**，仍是编译期强制，不能降级为 lint）；
- 单体 crate 的增量编译劣势在 3~5 万行以内可忽略；届时拆分对 AI 是纯机械活。

## 2. 核心接口契约

### 2.1 内核生命周期（`runtime/kernel.rs`）

```rust
pub struct Kernel { /* ctx, registry, bus, scheduler, domains, obs, state */ }

impl Kernel {
    pub fn init(cfg: KernelConfig) -> Result<Self>;      // 空间开辟
    pub async fn start(&self) -> Result<()>;             // 时间流启动
    pub async fn stop(&self) -> Result<()>;              // 时间流暂停（拒新 + drain）
    pub async fn destroy(self) -> Result<()>;            // 空间回收（逆序）

    pub fn handle(&self) -> KernelHandle;                // 交给 interfaces 的句柄
    pub async fn load(&self, manifest: PluginManifest) -> Result<PluginId>;
    pub async fn unload(&self, id: PluginId) -> Result<()>;
    pub async fn hotswap(&self, plan: HotSwapPlan) -> Result<HotSwapReport>;
}
```

**状态守护**：`KernelState` 保证 `start` 只能在 `init` 之后、`stop` 只能在 `start` 之后、`destroy` 只能执行一次（对应不变量 I1）。

### 2.2 插件契约 L3（`sdk`）

```rust
pub const API_VERSION: ApiVersion = ApiVersion::new(0, 1, 0);

#[async_trait]
pub trait Plugin: Send + Sync {
    // ★ A1：全部方法统一 `&self`。句柄恒为 `Arc<dyn Plugin>`，内核侧禁止出现
    //   `&mut self` / `self: Box<Self>` / `Arc<Mutex<dyn Plugin>>`。
    fn meta(&self) -> &PluginMeta;
    async fn init(&self, ctx: PluginContext, host: Arc<dyn HostApi>) -> Result<()>;
    async fn start(&self) -> Result<()>;                            // 注册订阅
    async fn on_event(&self, env: Envelope) -> Result<Option<Envelope>>;
    async fn drain(&self, timeout: Duration) -> Result<()>;         // 拒新 + 等在途
    async fn stop(&self) -> Result<()>;                             // 幂等
    async fn destroy(&self) -> Result<()>;                          // 幂等通知；真正的释放在 Drop
}

#[async_trait]
pub trait HostApi: Send + Sync {                                    // 宿主暴露给插件的能力
    async fn publish(&self, ev: Event) -> Result<EventId>;
    async fn subscribe(&self, pattern: EventPattern) -> Result<SubscriptionId>;
    async fn check_capability(&self, cap: &Capability) -> Result<()>;
    fn trace_id(&self) -> TraceId;
    fn config(&self) -> &PluginConfig;
}
```

**注意**：`trait Plugin` 是 **L3 方言**，不是契约源。跨语言与动态加载一律以 `schema/` 中的 **L2** 为准（见 `05`）。

**A1 · 接收者纪律（强制）**：`Plugin` 全部方法取 `&self`，插件内部可变性由插件自己承担（`Mutex` / `RwLock` / 原子量 / actor mailbox），**内核不提供任何共享可变包装**。由此：

- 句柄恒为 `Arc<dyn Plugin>`，注册表、路由表、调度器全程零锁；若实现中出现 `Arc<Mutex<dyn Plugin>>`，即为设计违规（内核分发路径上的互斥锁 = 死锁 + 串行化双杀）；
- `destroy(&self)` 是**幂等通知**（置停止标志、释放外部资源），真正的内存回收由 `Drop` 完成，故不取 `self: Box<Self>`（它与 `Arc` 共享互斥，会逼出所有权死结）；
- 泄漏检测下沉到测试：不变量 I1 断言 `Arc::strong_count(handle) == 1`。

### 2.4 注册表与状态机（`domain`）

```rust
pub trait Registry: Send + Sync {
    fn register(&self, meta: PluginMeta, h: DomainHandle) -> Result<PluginId>;
    fn unregister(&self, id: PluginId) -> Result<Registration>;
    fn route(&self, ty: &EventType) -> Arc<Vec<Subscription>>;   // 无锁读
    fn get(&self, id: PluginId) -> Option<Arc<Registration>>;
    fn generation(&self, id: PluginId) -> Option<Generation>;
    // ★ A4：CAS 语义，杜绝世代 ABA。`expected` = 调用方观测到的当前世代。
    //   非 CAS 的 `switch_generation(id, to)` 在"并发热替换 + 回滚"时会切到错误世代。
    fn compare_switch(
        &self,
        id: PluginId,
        expected: Generation,
        new: Generation,
    ) -> Result<(), GenerationMismatch>;
}

pub trait LifecycleManager: Send + Sync {
    fn transition(&self, id: PluginId, to: LifecycleState) -> Result<(), IllegalTransition>;
    fn state_of(&self, id: PluginId) -> Option<LifecycleState>;
}
```

### 2.5 能力与快照（`domain`）

```rust
pub trait CapabilityGate: Send + Sync {
    fn validate_manifest(&self, m: &PluginManifest) -> Result<()>;  // ApiVersion + Schema + 环检测
    fn check(&self, id: PluginId, cap: &Capability) -> Result<()>;  // 调用期拦截
}

pub trait Migratable {                                              // 可选能力
    // ★ M1 禁用迁移：全部 default 实现，返回类型化错误。严禁 `unimplemented!()`。
    fn snapshot(&self) -> Result<Snapshot> {
        Err(KernelError::Unsupported("migration not available in M1"))
    }
    fn restore(&self, s: Snapshot) -> Result<()> {                  // A1：统一 `&self`
        Err(KernelError::Unsupported("migration not available in M1"))
    }
    fn is_migratable(&self) -> bool { false }                       // 默认走"丢弃 + 冷启动"

```

### 2.6 事件模型（`core/event.rs`）

```rust
pub struct Envelope {
    pub trace_id: TraceId,
    pub span_id:  SpanId,
    pub event:    Event,          // { ty: EventType, payload: Bytes, source: PluginId }
    pub target:   Target,         // Unicast(PluginId) | Multicast(EventPattern) | Broadcast
    pub priority: Priority,       // Critical > High > Normal > Low
    pub deadline: Option<Duration>,// ★ A2：相对时长，**不是** `Instant`。
                                  //   `Instant` 是进程本地单调时钟，跨 ABI / 跨进程无意义，
                                  //   与 L2 的 `deadline-ms: option<u64>` / `deadline_ms` 语义漂移。
    pub generation: Option<Generation>,
}

pub enum TimeSemantics {
    Serial,       // 同一插件串行处理，严格保序
    Concurrent { max_inflight: u32 },  // 可并发，不保序
}

**A3 · WASM 域强制 `Serial`（强制）**：wasmtime 在 `Config::async_support(true)` 下，host 函数 await 期间**该 `Store` 不可重入**（再次 poll 即 trap）。而 `04` D2 规定"每个插件一个 `Store`" ⇒ **每个 WASM 插件同时只能有 1 个 in-flight 调用**，`Concurrent { max_inflight }` 对 WASM 域在物理上不可实现。故：

- 装载期校验：`manifest.domain == "wasm"` 且 `time.semantics == "concurrent"` ⇒ 直接 `Rejected`（`K202`），**不做静默降级**（静默降级会让"并发"在 WASM 下变成随机 trap）；
- WASM 域的并发只能靠"多 Store 实例"实现，属 M3+ 议题；M1 / M2 一律 `Serial`；
- `Serial` 语义的载体是**插件级 mailbox（actor）**，不是优先级泳道——泳道跨优先级取事件，无法保证单插件内保序（见 B5）。

pub enum DeliveryGuarantee { AtMostOnce, AtLeastOnce }  // 进程域默认 AtLeastOnce + 幂等键
```

**事件类型命名**：`domain.subject.action`，如 `llm.request.completed`、`tool.registry.updated`、`kernel.plugin.lifecycle`。订阅支持前缀通配 `llm.*`。

## 3. 执行流模式说明

### 3.1 三种基本形态的判定

| 形态 | 识别特征 | 本项目落点 |
|---|---|---|
| **顺序管道** | A → B → C 串行，无并发 | **装载 / 卸载 / 热替换用例**：必须严格按步骤推进，失败即回滚（事务时间线） |
| **事件循环 Loop** | `while let Some(env) = bus.recv().await` | **内核主循环**：所有插件的 `on_event` 由它驱动（主干） |
| **状态机跳转** | `match state { ... }` 驱动流转 | 两处：① 插件生命周期状态机（`LifecycleState`）；② Agent 主循环（感知→规划→行动→观察），**由编排插件实现，不属于内核** |

**结论：混合模式** —— 内核主干是事件循环；内核内部状态推进用状态机；管理类操作（装载/卸载/热替换）是顺序管道事务。

### 3.2 并发与背压

```
publish ─▶ [Critical 泳道 cap=1024] ┐
        ─▶ [High     泳道 cap=4096] ├─▶ 加权轮转 dequeue ─▶ 主循环分发
        ─▶ [Normal   泳道 cap=8192] │                        （每插件按 TimeSemantics
        ─▶ [Low      泳道 cap=2048] ┘                         决定串行 or 并发）
```

| 水位 | 策略 |
|---|---|
| < 70% | 正常 |
| 70%–90% | 记录 `backpressure.warning` 指标 |
| > 90% | 按 `BackpressurePolicy`：`Reject`（返回 `Busy`）/ `Block`（生产者等待，**必须带 deadline**）/ `DropOldest`（丢弃最旧 Low 优先事件并计数） |

**B4 · drain 与背压的循环等待（强制）**：in-flight 任务在 drain 期间仍会 `publish` 回事件总线。若目标泳道已满且策略为 `Block`，该任务永远等不到空位 ⇒ `DrainCoordinator` 计数永不归零 ⇒ 热替换必然超时 `K401`。故：

- 处于 `Draining` 世代的任务**豁免 `Block`**，一律退化为 `Reject`（返回 `K403`）；
- `Block` 策略必须携带 `deadline`，不得无限等待；
- `max_inflight` 必须由**调度器帧持有的 `Semaphore` 许可**实现（在 `tokio::spawn` **之前** acquire、permit 随任务所有权转移），不得在 spawned task 内部自行 acquire，否则并发度上限形同虚设。

**防饿死**：加权轮转保证 Low 泳道始终有配额（如 Critical:High:Normal:Low = 8:4:2:1）。

### 3.3 热替换时间线（顺序管道事务）

详见 `06-热替换与状态迁移.md`。此处仅给出执行流骨架：

```
validate → load(new) → [snapshot→transfer→restore] → start(new)
        → compare_switch(id, expected=g, new=g+1) → drain(old, timeout) → destroy(old)
        → 任一步失败 ⇒ rollback（compare_switch(id, expected=g+1, new=g) + destroy(new)）
```

## 4. 错误模型

### 4.1 错误码（`core/error.rs`，可跨 ABI 映射）

| 码段 | 类别 | 示例 |
|---|---|---|
| `K1xx` | 内核生命周期 | `K101` 重复 init、`K102` 未 init 即 start |
| `K2xx` | 装载 / 契约 | `K201` ApiVersion 不兼容、`K202` 清单 Schema 校验失败、`K203` 符号缺失、`K204` 循环依赖 |
| `K3xx` | 权限 | `K301` 未声明能力、`K302` 能力被策略拒绝 |
| `K4xx` | 时间流 | `K401` drain 超时、`K402` 事件超时、`K403` 背压拒绝 |
| `K5xx` | 执行域 | `K501` 插件 panic、`K502` WASM trap、`K503` 进程域连接中断 |
| `Pxxx` | 插件自定义 | 由插件自行定义并透传 |

### 4.2 边界纪律

- **panic 边界在每个执行域内部消化**，绝不允许跨越 `extern "C"` / WASM 边界（跨 FFI unwind 是 UB）。
- 域实现负责把 panic / trap / 连接中断统一转换为 `Result<_, KernelError>`。
- 进程内插件 panic → `Supervisor` 标记 `Failed`、卸载、按策略重启或隔离；**主循环继续**。

**B2 · `catch_unwind` 分支的唯一合法动作（强制）**：`catch_unwind` 保护的是**内核进程**，不是插件自身的一致性。panic 之后 `Arc<dyn Plugin>` 依然存活，而它内部的状态（已 poison 的 `Mutex`、已自增未回滚的计数器、半写入的缓存）已经损坏。因此：

- 捕获 panic 后的**唯一**合法动作是 `LifecycleManager::transition(id, Failed)` 并触发卸载；**严禁**仅 `return Err(K501)` 后让该插件继续接客——那会把"故障隔离"变成"静默数据损坏"；
- `AssertUnwindSafe` 是对编译器的**承诺**而非免死金牌：它只保证不 UB，不保证共享状态一致；
- `catch_unwind` **拦不住**：`process::abort`、栈溢出（SIGSEGV → abort）、OOM abort，以及在别处 `tokio::spawn` 的子任务中发生的 panic（后者由 tokio 收敛为 `JoinError::panic`，须用 `JoinSet` 单独回收检查）。

**B2' · Rust async 的第三类失败——被 drop（取消）**：失败不止 `Err` 与 `panic` 两种。future 被丢弃（deadline 到期、`stop()` 撤 token、热替换 abort）时 RAII 会正常跑，但**跨 `.await` 的业务不变量不会自愈**（如"先扣额度再调 LLM，被取消后额度未归还"）。故：

- `DrainCoordinator` 只保证"不再接新活"，**不保证被取消的活是干净的**；
- 需要补偿语义的插件须自行实现幂等键 / 事务日志；内核只提供注入点，不提供通用补偿。

## 5. 配置模型

```toml
# kernel.toml
[kernel]
api_version = "0.1.0"
shutdown_timeout = "10s"

[bus]
lane.capacity = { critical = 1024, high = 4096, normal = 8192, low = 2048 }
backpressure = "reject"          # reject | block | drop_oldest

[domain.in_process]
enabled = true

[domain.wasm]
enabled = false
fuel_limit   = 1_000_000        # 指令级燃料：只防纯计算死循环
epoch_tick   = "10ms"           # B3：墙钟级上限，配合 epoch_interruption
host_timeout = "5s"             # B3：单个 host call 的硬性超时

[domain.process]
enabled = false
endpoint_timeout = "5s"

[observability]
otlp_endpoint = "http://127.0.0.1:4317"
log_level = "info"

[plugins]
auto_load = ["llm-adapter", "tool-registry"]
```

**B3 · WASM 时间维度的三重上限（强制）**

| 上限 | 机制 | 拦什么 |
|---|---|---|
| `fuel_limit` | 指令计数耗尽即 trap | 纯计算死循环（**不计费 host call**） |
| `epoch_tick` | `Config::epoch_interruption(true)` + 定时器线程周期性 `Engine::increment_epoch()` | guest 执行的墙钟兜底 |
| `host_timeout` | 每个 host call 用 `tokio::time::timeout` 包裹 | 慢 host 函数把 `Store` 占死 |

**关键点**：`fuel` 与 `epoch` 只推进在 **guest 指令**上，**host 函数调用期间两者都不推进**。因此"插件反复调用一个慢 host 函数"是唯一无法被前两者拦截的攻击面，必须靠 `host_timeout` 单独兜底。此外 host call 的耗时**必须计入插件的 `deadline`**。

**补充**：`05` 的 `world agent-plugin { import host-api; export plugin; }` 未 import `wasi:sockets`，guest 在结构上**没有能力**发起网络请求。因此"WASM 插件禁止直接联网"已由 world 定义强制，无需在 prompt 中重复下禁令；真正要防的是实现时在 `WasiCtxBuilder` 上顺手 `inherit_network()` / 挂载 `wasi:sockets`。

## 6. 版本与兼容策略

| 项 | 策略 |
|---|---|
| `ApiVersion` | semver：`major` 不兼容、`minor` 向后兼容新增、`patch` 无契约变化 |

# agent-kernel 架构设计

> 本文档回答**为什么这样选**。所有选型均由"空间 / 时间 / 规则"三项时空需求直接推导，而非惯例驱动。

### 1.4 时间视图：一次事件的时间线

```
publish(event)
   │
   ├─[1] 分配 trace_id（ULID），构造 Envelope{priority, deadline}
   ├─[2] 入优先级泳道（有界队列；满则触发背压策略）
   ├─[3] 主循环 recv() 加权取出
   ├─[4] Observability: 开 span（trace_id 入 span 上下文）
   ├─[5] Registry.route(event.ty) → 命中订阅者列表（已按 priority 排序）
   ├─[6] 对每个订阅者：
   │      ├─ CapabilityGate.check(plugin, Bus::Subscribe(ty)) —— 规则拦截
   │      ├─ DrainCoordinator.acquire(gen) —— 若在 draining 则拒新
   │      ├─ 按 time_semantics 决定 Serial（串行保序）/ Concurrent（spawn+取消）
   │      ├─ ExecutionDomain.dispatch() —— 域内执行（panic 边界在此）
   │      └─ 结果写回；错误 → record_error + 可选 PluginFailed 事件
   └─[7] 闭 span；trace 经 infrastructure 导出
```

### 1.5 物理视图（部署）

单机进程形态。三种执行域在空间上的落点：

| 域 | 空间落点 | 崩溃影响域 | 调用开销量级 |
|---|---|---|---|
| `InProcess` | 内核进程堆内（`Arc<dyn Plugin>`） | 由 `catch_unwind` 收敛到单插件 | ~亚微秒 |
| `Wasm` | 内核进程内 wasmtime 线性内存 | 单实例（trap 可捕获） | ~微秒 |
| `Process` | 独立 OS 进程 | 单进程（可自愈重启） | ~0.1–1 ms（IPC/gRPC） |

## 2. 技术选型（逐项由时空需求推导）

| 选型 | 满足的时空需求 | 理由 | 被放弃的替代方案 |
|---|---|---|---|
| **Rust** | **空间**：所有权 / 借用 / RAII 使"每次 init 必有 destroy"可由类型系统保障，热替换时不产生悬垂指针；**规则**：trait + 泛型把契约检查前移到编译期；**生态**：WASM 组件模型最成熟 | 唯一同时满足"确定性空间回收 + 编译期规则校验 + 强隔离宿主"的主流系统语言 | Go（GC 无法确定性回收；无所有权规则；WASM 支持弱）／TypeScript（无内存隔离、无编译期规则）／C++（无统一包管理与安全兜底） |
| **tokio**（异步运行时） | **时间**：以极小成本承载成百上千条并发执行流；`CancellationToken` 提供统一的时间流取消原语 | 与"事件循环 + 多插件并发 + drain 超时"天然契合 | 裸线程（成本高、难规模化）／自研调度器（重复造轮子） |
| **tokio::sync::mpsc（有界）+ watch + broadcast** | **时间 + 规则**：**有界**是背压的物理前提（无限队列 = 必然 OOM）；**状态类（生命周期 / 配置可用性）用 `watch`**（最新值、可重放，订阅即得当前态），**事件类（审计 / 指标）用 `broadcast`**（B1） | 有界队列把"时间流过载"转化为可策略化的规则问题；`watch` 消除 `broadcast` 的 `Lagged` 静默丢状态风险 | 无界队列（失去背压）／crossbeam（无 async 背压语义） |
| **arc-swap** | **空间**：注册表以 `ArcSwap` 整体原子替换，读侧无锁；这是热替换"原子切换"的物理来源 | 换代时读侧永不阻塞、永不读到半替换状态 | `RwLock<HashMap>`（读侧竞争；持锁期间可能撕裂） |
| **wasmtime + component-model（wit）** | **空间**：线性内存天然无跨插件互访；**规则**：wit 类型系统在装载期校验；**跨语言**：L2 线协议的 WASM 载体 | 强隔离与跨语言的交点，且性能近原生 | wasmer（组件模型与工具链成熟度较弱） |
| **tonic + prost（protobuf）** | **规则**：有 Schema、可生成多语言 stub；**空间**：跨进程边界无共享内存 | 落实默认决策 **D1 先进程域 / D2 protobuf** | JSON-RPC（无 schema、无 stub、payload 大）／Cap'n Proto（性能好但生态与工具链小） |
| **serde + toml + serde_json** | **规则**：清单与配置的解析即校验 | TOML 清单（决策 D4）人类可写，JSON 用于 Schema 校验与网络传输 | 自研解析器（无校验能力） |
| **schemars + jsonschema** | **规则**：由 Rust 类型**生成** JSON Schema，使 L1 契约与代码保持单一事实源 | 避免"文档说一套、代码做一套"的规则漂移 | 手写 JSON Schema（必然漂移） |
| **tracing + tracing-subscriber + opentelemetry-otlp** | **时间**：span 天然跨 `await` 点传播，是 `trace_id` 串联的物理载体 | 内核承担可观测性的最小可信实现 | 自研日志（无法跨插件 / 跨 await 串联） |
| **petgraph** | **时间**：拓扑排序决定装载顺序，环检测阻止非法时间流 | 依赖图算法成熟可靠 | 手写 DFS（易错、难测） |
| **thiserror（core）/ anyhow（application）** | **规则**：把错误建模为可枚举的错误码，跨 ABI 可映射 | core 层错误必须可序列化过 ABI 边界 | 裸字符串错误（无法跨语言映射） |
| **catch_unwind + panic=unwind** | **规则**：把进程内插件的 panic 收敛为一次调用失败，主循环不死 | 落实"任意插件崩溃不得拖垮内核"；**捕获后唯一合法动作 = `transition(id, Failed)` + 卸载**（B2），严禁仅 `return Err` 后继续服务 | 不隔离（一个插件 panic 全内核崩） |
| **ULID / UUIDv7（trace_id）** | **时间**：ID 本身时间有序，便于按时间切片检索链路 | 比 UUIDv4 更契合时间语义 | UUIDv4（无序） |

**关键约束提醒**：`catch_unwind` 不得跨越 `extern "C"` 边界（跨 FFI unwind 是 UB）。因此 panic 边界必须**在每个执行域内部**消化，域实现负责把 panic 转成 `Result`；捕获点之后的唯一动作是标记 `Failed` 并卸载（B2）。

## 3. 依赖方向铁律（时空防越界）与强制手段

### 3.1 规则

| 铁律 | 内容 | 物理含义 |
|---|---|---|
| **空间防越界** | `infrastructure` 绝不能反向依赖 `domain` 的具体实现；`domain` 只依赖 `infrastructure` 的**抽象接口**（由 `core` 定义，运行期注入） | 底层存储不得直接操作业务空间 |
| **时间防乱序** | `domain` 不得调用 `runtime` 的调度器；只暴露事件 / 状态，由 `application` 编排后交 `runtime` 驱动 | 业务不得自我驱动时间流 |
| **规则防穿透** | 所有跨层访问必须经 `core` 定义的接口或 `interfaces` 定义的契约；插件**只依赖 `sdk`**，禁止依赖 `kernel` 内部模块 | 禁止越权操作非本层内存 |

### 3.2 静态强制手段（不可仅靠约定）

| 手段 | 检查内容 | 落地方式 |
|---|---|---|
| **crate 物理边界** | 每层是独立 crate，依赖只能是 Cargo 依赖 | workspace 布局 |
| **依赖白名单** | `core` 的 `Cargo.toml` 中除基础库外无 path 依赖 | `cargo-deny` / 自定义 `xtask arch-check` |
| **插件依赖守卫** | `plugins/*/Cargo.toml` 仅允许依赖 `sdk`（+ 自身第三方库白名单） | CI 脚本扫描，违规即失败 |
| **架构测试** | 断言 `domain` 源码中不出现 `infrastructure::` 具体类型路径 | `assert_cmd` 风格的源码扫描测试 |
| **CI 门禁** | `cargo fmt --check` + `cargo clippy -D warnings` + 上述守卫测试 | CI pipeline |

## 4. 质量属性与权衡

| 属性 | 目标 | 权衡与代价 |
|---|---|---|
| **隔离性** | 不可信插件无法读写内核或其他插件内存 | 进程内域靠类型系统与 `catch_unwind` 保证（较弱），故不可信插件默认走 WASM / Process 域 |
| **热替换零停机** | 换代期间服务不中断、请求不丢失 | 短暂**双版本共存**（内存与 CPU 有瞬时翻倍），以可用性优先换取一致性延迟 |
| **时间流不撕裂** | in-flight 请求必被 drain | drain 超时需**强制推进**（可能截断长任务），故插件须声明 `deadline` |
| **演进性** | 内核 API 演进不破坏既有插件 | `ApiVersion` semver + 兼容矩阵测试；重大变更走 v2 线协议并存 |
| **可观测性** | 任意请求可跨插件、跨域重建调用链 | 内核必须为每次分发分配与传递 `trace_id`，有固定 CPU 开销（约 1–2%） |
| **性能** | 常见路径（事件分发）延迟可控 | 优先级泳道 + 预排序路由 + 无锁读注册表，避免热路径加锁 |

## 5. ADR 摘要（架构决策记录）

| # | 决策 | 结论 | 依据 |
|---|---|---|---|
| ADR-001 | 内核边界 | **纯内核**：内核只提供空间 / 时间 / 规则原语；一切能力皆为插件 | `program.md` 纯内核边界表（已确认） |
| ADR-002 | 契约唯一源 | **L2 线协议为唯一契约源**；`trait Plugin` 降级为 L3 语言绑定；新增 `schema/` | Rust 无稳定 ABI，`Box<dyn Plugin>` 跨动态库边界存在 UB 风险 |
| ADR-003 | 隔离机制 | **混合多执行域**：核心可信插件进程内，不可信 / 需强隔离走 WASM 或进程；统一为 `trait ExecutionDomain` | 隔离强度与性能的连续谱，单一方案无法覆盖 |
| ADR-004 | 跨语言优先序 | **先进程域**（对语言最宽容、调试友好） | 默认决策 D1 |
| ADR-005 | 进程域传输格式 | **protobuf**（有 Schema，可生成 stub） | 默认决策 D2 |
| ADR-006 | 是否保留 Rust 进程内域 | **保留**（同语言零开销快车道） | 默认决策 D3 |
| ADR-007 | 插件清单格式 | **TOML + JSON Schema 校验**（Schema 由 Rust 类型经 `schemars` 生成） | 默认决策 D4 |
| ADR-008 | 可观测性归属 | **内核承担**跨插件 `trace_id` 串联 | 插件自打日志无法完成链路追踪（易漏项） |
| ADR-009 | 执行域适配器归属 | 属于**内核，不是插件** | 它们是时空规则的执行者，而非被装载的能力单元 |
| ADR-010 | drain 超时策略 | 超时后**强制推进**并标记 `Failed`，不无限等待 | 防止热替换被长任务永久阻塞（时间死锁） |
| ADR-011 | 能力门控默认值 | **deny-by-default**，插件须显式声明 | 规则防线默认关闭 |
| ADR-012 | 注册表替换语义 | 换代用 `ArcSwap` 整体原子替换，不原地改写 | 保证读侧永不观察半替换状态（空间不撕裂） |

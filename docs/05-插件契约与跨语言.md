# 插件契约与跨语言

> **核心修正**：插件接口**不是**单一接口，而是三层。`core::Plugin` 一肩挑三职（语义 + ABI + 语言绑定）会导致跨语言与动态加载均不可行。

---

## 1. 问题陈述

| 现象 | 根因 |
|---|---|
| `Box<dyn Plugin>` 无法跨动态库边界安全传递 | Rust **无稳定 ABI**；`dyn Trait` 的 vtable 布局不受 ABI 保证 |
| 跨语言插件无协议可依 | 契约只存在于 Rust 类型系统内，对外不可见 |
| 进程内 / WASM / 进程域三套接口各行其是 | 缺少统一的中间契约层 |

**结论（ADR-002）**：`trait Plugin` 降级为 **L3 语言绑定**；以 **L2 线协议为唯一契约源**；新增 `schema/` 目录承载。

---

## 2. 三层契约模型

```
┌──────────────────────────────────────────────────────────────┐
│ L1 语义契约（语言无关 · 文档 + JSON Schema）                   │
│   身份 / 能力 / 事件模型 / 生命周期 / 状态 / 错误 / 时间语义    │
│   载体：plugin-manifest.schema.json · capability.schema.json  │
└───────────────────────────────┬──────────────────────────────┘
                                ↓ 形式化
┌──────────────────────────────────────────────────────────────┐
│ L2 线协议 / ABI（语言无关 · ★唯一契约源★）                     │
│   kernel.wit   （WASM 组件模型）                              │
│   kernel.proto （进程域 gRPC）                                │
│   （进程内域直接由 L2 生成 Rust 绑定，语义等价）                │
└───────────────────────────────┬──────────────────────────────┘
                                ↓ 方言化
┌──────────────────────────────────────────────────────────────┐
│ L3 语言绑定（语言有关 · 由 L2 生成或手写）                     │
│   Rust trait（sdk::Plugin） · Python ABC · TS interface        │
└──────────────────────────────────────────────────────────────┘
```

| 层级 | 名称 | 语言相关 | 载体 | 变更成本 | 说明 |
|---|---|---|---|---|---|
| **L1** | 语义契约 | 无关 | 文档 + JSON Schema | 低 | 人读的规范，规定"意味着什么" |
| **L2** | 线协议（ABI） | 无关 | `kernel.wit` / `kernel.proto` | **高** | **真正的插件接口**，规定"字节怎么走" |
| **L3** | 语言绑定 | 有关 | Rust trait / Python ABC / TS interface | 中 | 仅是 L2 的一种方言，可生成 |

**关键推论**：混合执行域不是"性能 vs 隔离"的权衡，而是**契约层级的分野** ——

- **进程内域** = 同语言快车道（L2 的 Rust 直连实现，零序列化）
- **WASM / 进程域** = 跨语言通用道（L2 的序列化实现，可跨语言）

## 3. L1 语义契约

### 3.1 插件清单（TOML + JSON Schema，ADR-007）

```toml
# plugin.toml
id          = "llm-adapter"
name        = "LLM Adapter"
version     = "0.3.1"
api_version = "0.1.0"                 # 面向内核的契约版本
domain      = "in-process"            # in-process | wasm | process

[entry]
# in-process: cdylib 路径；wasm: .wasm 组件路径；process: 可执行文件路径
path = "target/release/libllm_adapter.so"

[capabilities]
net_outbound = ["api.openai.com", "api.anthropic.com"]
env_read     = ["LLM_API_KEY"]
bus_publish  = ["llm.*"]
bus_subscribe= ["agent.request.*"]

[depends_on]
tool-registry = { version = "^0.2", kind = "soft" }

[time]
semantics = "serial"                  # serial | concurrent
max_inflight = 8
deadline  = "30s"

[migration]
migratable = false           # ★ M1 恒为 false；见下方"迁移禁用条款"
format     = "bincode:1"
```

> **[time] 段补充约束**：`semantics = "concurrent"` 与 `domain = "wasm"` **互斥**（A3）。wasmtime 的 `Store` 在 host call await 期间不可重入，每个 WASM 插件同时只能有 1 个 in-flight 调用。装载期校验到此组合即 `Rejected`（`K202`），**不做静默降级**。

> **迁移禁用条款（M1，强制）**：`Migratable` 在 `sdk` 中以 **default method** 提供，默认返回 `Err(KernelError::Unsupported)`，`is_migratable()` 默认 `false`。
> **严禁 `unimplemented!()` / `todo!()` / `panic!()`** —— 在一个以"插件 panic 不拖垮内核"为核心卖点的项目里，在 SDK 热路径上放 panic 宏是自毁招牌。M4 只需在插件侧 override 即可启用迁移，无需改动内核。
> 附带收益：M1 会把"丢弃 + 冷启动"路径打磨到极致，而冷启动是**所有迁移失败的永久兜底**。

**校验链路**：`serde` 反序列化 → `schemars` 生成的 JSON Schema 校验 → `CapabilityGate::validate_manifest`（`ApiVersion` 兼容 + 能力合法性 + 环检测）。

> Schema 由 `core::manifest::*` 经 `schemars` **生成**，杜绝"文档与代码双份真相"。

### 3.2 语义条款（L1 必须写明的七件事）

| # | 条款 | 内容 |
|---|---|---|
| 1 | **身份** | `id` 全局唯一（命名空间 + 名称），不可与其他插件冲突 |
| 2 | **能力** | 插件可读写的外部空间清单；**未声明即禁止**（deny-by-default） |
| 3 | **事件模型** | 事件类型命名 `domain.subject.action`；`Envelope` 字段语义；订阅通配规则 |
| 4 | **生命周期** | `init/start/on_event/drain/stop/destroy` 的调用时机、顺序、可失败性 |
| 5 | **状态** | `PluginContext` 私有；跨插件不可见；`Migratable` 为可迁移声明 |
| 6 | **错误** | 错误码分段（`Kxxx` 内核 / `Pxxx` 插件）；错误必须可序列化过 ABI |
| 7 | **时间语义** | `serial` / `concurrent`、超时 `deadline`、投递保证（`at_most_once` / `at_least_once` + 幂等键）、drain 义务 |

## 4. L2 线协议

### 4.1 WASM：`schema/kernel.wit`（组件模型）

```wit
package agent-kernel:plugin@0.1.0;

interface types {
    record envelope {
        trace-id: string,
        span-id:  string,
        ty:       string,
        payload:  list<u8>,
        priority: u8,
        deadline-ms: option<u64>,
    }
    record plugin-meta {
        id: string,
        version: string,
        api-version: string,
    }
    variant kernel-error {
        contract-mismatch(string),
        capability-denied(string),
        timeout(string),
        trap(string),
        plugin-failed(string),
    }
}

interface host-api {                      // 内核 → 插件（宿主能力）
    use types.{envelope, kernel-error};
    publish: func(ev: envelope) -> result<string, kernel-error>;
    check-capability: func(cap: string) -> result<_, kernel-error>;
    trace-id: func() -> string;
}

interface plugin {                        // 插件 → 内核（必须导出）
    use types.{envelope, plugin-meta, kernel-error};
    meta: func() -> plugin-meta;
    init: func(cfg-json: string) -> result<_, kernel-error>;
    start: func() -> result<_, kernel-error>;
    on-event: func(ev: envelope) -> result<option<envelope>, kernel-error>;
    snapshot: func() -> result<list<u8>, kernel-error>;
    restore: func(payload: list<u8>) -> result<_, kernel-error>;
    drain: func(timeout-ms: u64) -> result<_, kernel-error>;
    stop: func() -> result<_, kernel-error>;
    destroy: func() -> result<_, kernel-error>;
}

world agent-plugin {
    import host-api;
    export plugin;
}
```

### 4.2 进程域：`schema/kernel.proto`（gRPC，ADR-005）

```proto
syntax = "proto3";
package agentkernel.v1;

service PluginService {
  rpc Meta(Empty)                 returns (PluginMeta);
  rpc Handshake(HandshakeReq)     returns (HandshakeResp);   // ApiVersion 协商
  rpc Init(InitReq)               returns (InitResp);
  rpc Start(Empty)                returns (Empty);
  rpc OnEvent(stream Envelope)    returns (stream Envelope); // 双向流：trace_id 经 metadata
  rpc Snapshot(Empty)             returns (SnapshotResp);
  rpc Restore(SnapshotReq)        returns (Empty);
  rpc Drain(DrainReq)             returns (DrainResp);
  rpc Stop(Empty)                 returns (Empty);
  rpc Destroy(Empty)              returns (Empty);
  rpc Health(Empty)               returns (HealthResp);
}

message Envelope {
  string trace_id = 1;
  string span_id  = 2;
  string ty       = 3;
  bytes  payload  = 4;
  uint32 priority = 5;
  optional uint64 deadline_ms = 6;
  string idempotency_key = 7;
}

message PluginMeta { string id = 1; string version = 2; string api_version = 3; }

enum ErrorCode {
  ERROR_CODE_UNSPECIFIED = 0;
  K201_CONTRACT_MISMATCH = 201;
  K301_CAPABILITY_DENIED = 301;
  K401_DRAIN_TIMEOUT     = 401;
  K501_PLUGIN_PANIC      = 501;
  K503_DOMAIN_DISCONNECT = 503;
}
```

**握手协议**：进程启动后先 `Handshake`，双方交换 `api_version` 与支持的能力集；不兼容则子进程自行退出并返回非零码（装载期 `Rejected`）。

### 4.3 进程内域与 L2 的关系

进程内域**不**跳过 L2：Rust 侧绑定（L3）由 L2 定义**手工对齐**（字段与语义一一对应），并用一组契约一致性测试守护：

```rust
// crates/runtime/src/domain/in_process.rs —— 契约一致性测试
#[test]
fn l3_binding_matches_l2_shape() {
    // 断言 sdk::Plugin 的方法签名集合 == kernel.wit 中 interface plugin 的函数集合
    // 断言 Envelope 字段集合与类型 == kernel.proto 的 Envelope
}
```

CI 中校验 `kernel.wit` / `kernel.proto` 的函数名集合一致，防止两版 L2 漂移。

## 5. L3 语言绑定

| 语言 | 形态 | 生成方式 | 状态 |
|---|---|---|---|
| **Rust** | `sdk::Plugin` trait + `#[plugin]` 宏 | 手写（与 L2 对齐 + 契约测试守护） | M1 首批 |
| **Python** | ABC + 进程域 SDK（gRPC 客户端封装） | `kernel.proto` → `grpcio-tools` 生成 | M2 |
| **TypeScript** | interface + 进程域 SDK | `kernel.proto` → `ts-proto` 生成 | M2 |
| **其他** | 任意可跑 gRPC 的语言 | 直接实现 `kernel.proto` | M2+ |

**Rust 侧**（`crates/sdk`，插件唯一可见依赖）：

```rust
#[async_trait]
pub trait Plugin: Send + Sync { /* meta/init/start/on_event/drain/stop/destroy */ }

#[macro_export]
macro_rules! plugin {                       // 生成 C 兼容导出符号，供 dlopen 装载
    ($t:ty) => { ... };                     // 导出 _kernel_plugin_create / _kernel_plugin_meta
}
```

> **禁止**：插件 crate 依赖 `runtime` / `domain` / `infrastructure`。CI 扫描 `plugins/*/Cargo.toml`，违规即失败（规则防穿透）。

## 6. 契约演进

| 变更类型 | 版本位 | 处理方式 |
|---|---|---|
| 新增可选字段 / 新增可选方法 | `minor` | 旧插件无需改动；内核对未实现方法走默认分支 |
| 新增必填字段 / 修改语义 | `major` | 新增 v2 线协议（新 world / 新 proto package），**双栈并存**一段时间 |
| 文档与 typo | `patch` | 无契约影响 |

**兼容矩阵守护（不变量 I3）**：CI 中以"历史版本插件 × 当前内核"跑装载测试，任一条目失败即阻断发布。

## 7. 目录与产出物

```
schema/
├── kernel.wit                  # L2（WASM 域）
├── kernel.proto                # L2（进程域）
├── plugin-manifest.schema.json # L1（由 core::manifest 经 schemars 生成，勿手改）
└── capability.schema.json      # L1（由 core::capability 生成，勿手改）
```

**生成命令**（CI 中执行，产出与代码不一致即失败）：

```bash
cargo run -p xtask -- gen-schema   # 重新生成 L1 Schema
cargo run -p xtask -- check-abi    # 校验 wit / proto / Rust 绑定三者一致（★ 字段级）
cargo run -p xtask -- layering     # 校验 crate 分层与插件依赖白名单
```

**`check-abi` 必须做到字段级（强制，C3）**：只比对"函数名集合"远远不够——它抓不到**类型漂移**。本方案文档中已存在一例真实漂移：`core::Envelope.deadline: Option<Instant>`（进程本地单调时钟，不可序列化）vs wit `deadline-ms: option<u64>` vs proto `optional uint64 deadline_ms`（均为相对时长）。函数名全对，语义完全不同。

`check-abi` 最低验收标准：

| 检查项 | 内容 |
|---|---|
| 函数集合 | wit `interface plugin` / proto `service PluginService` / `sdk::Plugin` 三者函数名一致 |
| **字段集合** | `Envelope` / `PluginMeta` 在三种载体下的字段名**规范化后**（kebab-case ↔ snake_case ↔ lowerCamel）一一对应 |
| **类型映射** | 每张字段的类型必须落在预置映射表内（如 `option<u64>` ↔ `optional uint64` ↔ `Option<Duration>` 合法；`Instant` ↔ `u64` **非法**） |
| **可序列化性** | 出现在 `Envelope` 中的每个 Rust 类型都必须实现跨 ABI 可序列化；**禁止 `Instant` / `Arc` / 裸引用 / 非 `'static` 借用** |
| 错误码 | 三者错误码枚举可双向映射 |

## 8. 检查清单（跨语言相关）

- [ ] `kernel.wit` 与 `kernel.proto` 的函数集合一致
- [ ] Rust `sdk::Plugin` 与 L2 函数集合一致（契约测试守护）
- [ ] 所有错误码可序列化且跨语言可映射
- [ ] 清单 Schema 由代码生成，未手工修改
- [ ] 插件 crate 依赖白名单通过（仅 `sdk`）
- [ ] 进程域握手失败时子进程非零退出
- [ ] WASM 域设置 `fuel_limit` + `epoch_tick` + `host_timeout` 三重时间上限（B3）
- [ ] WASM 域未挂载 `wasi:sockets`，`WasiCtxBuilder` 未 `inherit_network()`（B3）
- [ ] 装载期拒绝 `domain = "wasm"` + `semantics = "concurrent"` 的组合（`K202`）（A3）
- [ ] 示例非 Rust 插件（Python/TS）可跑通装载与事件流转（M2 验收）

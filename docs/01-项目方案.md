## 项目目标

构建一个 **Agent 运行时内核（Agent Runtime Kernel）**。内核自身只承担三件物理职责：

1. **开辟并隔离插件的空间** —— `PluginContext` 归属、跨插件零互访、快照与迁移协议；
2. **编排插件的执行时间流** —— 事件总线、调度器、生命周期状态机、drain 与背压；
3. **强制校验插件契约与权限** —— `ApiVersion` 协商、`Capability` 门控、依赖图环检测、panic 隔离、`trace_id` 串联。

所有具体能力（LLM 适配器、工具、记忆、规划/编排、提示词模板、向量库……）一律以**插件**形式挂载，并支持**不停机热替换**。

**首批交付**：完整内核（生命周期 / 调度器 / 注册表 / 多执行域）+ 1~2 个骨架插件（LLM 适配器、工具注册），跑通"装载 → 事件流转 → 热替换 → 卸载"闭环。

## 本质定义（已通过时空契约校验）

> **agent-kernel 是一个以"插件即能力"为第一原则的 Agent 运行时空管家：内核 = 空间隔离 + 时间调度 + 规则校验；插件 = 可被挂载 / 卸载 / 热替换的能力单元。**

### 时空契约校验（硬性门槛）

| 公理维度 | 契约内容 | 违反后果 |
|---|---|---|
| **空间** | 每个插件独占一个 `PluginContext`（自身状态 / 配置 / 资源句柄）；内核持有只读共享 `KernelContext`（全局配置 + 事件总线发送端）。插件间**禁止直接内存互访**，跨插件通信一律经事件总线。热替换时旧状态需"可丢弃"或"可快照迁移"。 | 插件可读写彼此内存 → 隔离形同虚设；热替换造成悬垂指针 |
| **时间** | 主执行流为**事件循环 Loop**（`while let Some(env) = bus.recv().await`）；插件通过注册 `on(event)` 回调接入。Agent 主循环本身是**状态机**（感知→规划→行动→观察），由"编排插件"（其自身也是插件）驱动。 | 时间流撕裂：in-flight 请求在替换瞬间丢失 |
| **规则** | 编译期以 `trait Plugin` + `ApiVersion` 限定接口；装载期校验符号/契约 + 能力声明（`Capability`）。不满足同版本契约 → **拒绝加载**。 | 规则穿透 → 内核崩溃 |

### 类归属

**微内核（Microkernel）家族** —— 与 L4/QNX、Kubernetes、VSCode Extension Host、Envoy 同族：内核只提供"空间 / 时间 / 规则"原语，能力全部外置并通过标准契约接入。

**不属于**：能力框架 / 库（LangChain、AutoGen 类）——编译期绑定、同进程共享内存，无隔离、无热替换、无能力门控，缺"运行时"语义。

### 关键属性展开

| # | 属性 | 展开 |
|---|---|---|
| A1 | **纯内核边界** | 内核只提供原语：`Registry` 归属表、`PluginContext`/`KernelContext` 边界、事件总线与 `Scheduler`、`LifecycleState` + drain、`ApiVersion`/`Capability`/环检测/panic 隔离/`trace_id`。状态存放、记忆、向量、文件、模型调用、业务策略——**全部下沉为插件** |
| A2 | **三层插件契约** | L1 语义契约（语言无关，文档 + JSON Schema）→ L2 线协议 ABI（`kernel.wit` / `kernel.proto`，**唯一契约源**）→ L3 语言绑定（Rust trait / Python ABC / TS interface） |
| A3 | **多执行域** | `InProcessDomain`（`Arc<dyn Plugin>`，同语言零开销快车道）/ `WasmDomain`（wasmtime 组件模型，跨语言强隔离）/ `ProcessDomain`（gRPC + protobuf，跨语言最宽容）。统一抽象为 `trait ExecutionDomain` |
| A4 | **热替换零停机** | 注册表原子替换（`ArcSwap`）+ 旧版本进入 `Draining`（拒新、收尾）+ drain 超时强制回收 + `Generation` 版本号区分新旧 |
| A5 | **依赖图** | 插件声明 `depends_on`；装载前拓扑排序；环检测拒绝；卸载按**逆拓扑序** |
| A6 | **可观测性内建** | 内核统一分配 `trace_id`，跨插件 span 串联。插件自打日志无法完成链路追踪，故此项为**内核职责（易漏项）** |
| A7 | **故障隔离** | 进程内插件每次调用包裹 `catch_unwind`；WASM/进程域天然隔离；单个插件 panic → 标记 `Failed` 并卸载，不影响内核与其他插件。**捕获后的唯一合法动作是 `transition(id, Failed)` + 触发卸载，严禁仅返回 `Err` 后让插件继续接客**（B2） |
| A8 | **插件依赖方向** | 插件**只依赖 `sdk`**，禁止依赖 `kernel` 内部模块（防规则穿透与编译耦合） |

### runtime/ 设计（时空管家核心）

```rust
// 文件：crates/runtime/src/kernel.rs
pub struct Kernel {
    ctx:       Arc<KernelContext>,   // 只读共享空间（全局配置 + 事件发送端）
    registry:  Arc<Registry>,        // 空间归属表（ArcSwap 原子替换）
    bus:       Arc<EventBus>,        // 时间流载体（有界多泳道 mpsc + broadcast）
    scheduler: Scheduler,            // 时间编排（优先级 + 并发度 + 背压）
    domains:   DomainTable,          // InProcess / Wasm / Process
    obs:       Arc<Observability>,   // trace_id 串联
    state:     KernelState,          // 守护 init/start/stop/destroy 的合法顺序
}

impl Kernel {
    pub fn init(cfg: KernelConfig) -> Result<Self>;      // 空间开辟
    pub async fn start(&self) -> Result<()>;             // 时间流启动（主循环）
    pub async fn stop(&self) -> Result<()>;              // 时间流暂停（拒新 + drain）
    pub async fn destroy(self) -> Result<()>;            // 空间回收（依赖逆序 drop）
}
```

主循环形态（**事件循环 Loop**）：

```rust
// 文件：crates/runtime/src/scheduler.rs
pub async fn run(&self, shutdown: CancellationToken) {
    while let Some(env) = self.bus.recv().await {
        if shutdown.is_cancelled() { break; }            // 停止接收新事件（stop）
        let span = self.obs.span_for(&env.trace_id);     // 规则：trace 串联
        let targets = self.registry.route(&env.event.ty).await;
        for t in targets {                               // 时间分发
            if let Err(e) = self.dispatch(t, env.clone()).await {
                self.obs.record_error(t, &e);            // 单插件失败不阻断主循环
            }
        }
    }
}
```

## 模块递归四层设计（强制带生命周期钩子）

每个核心模块统一暴露四个钩子：

- `init(ctx)`：**空间开辟**、依赖注入（对应分配内存）
- `start()`：**时间流启动**（注册订阅 / 拉起调度任务）
- `stop()`：**时间流暂停**（拒新事件、进入 drain）
- `destroy()`：**空间回收**，按依赖逆序释放（对应释放内存，防止悬垂指针）

> 递归规则：第1层锚定项目本质，第2层起强制锚定父本质，格式 `在"{父本质定义}"的时空约束下，本子模块的本质是……`；超过 3 层终止。

### 模块 A：Registry — 空间归属表（`domain/registry`，第1层）

- **本质（锚定父本质 + 时空契约）**：在"内核负责开辟与隔离插件空间"的时空约束下，本模块的本质是 **插件身份与其私有空间绑定关系的唯一权威账本，以及插件间依赖关系的有向图**。
- **数据规范**：`PluginId`、`Generation`、`PluginMeta{id, api_version, domain, capabilities, depends_on, time_semantics}`、`Registration{plugin_id, meta, state, generation, ctx}`。
- **数据存储**：常驻内存 `ArcSwap<HashMap<PluginId, Registration>>`（读多写少，换代时整体原子替换）；插件包与清单由 `infrastructure/` 落盘；可选快照后端持久化注册索引。
- **数据流转**：路由表（事件类型 → 订阅者集合）在装载/卸载时**增量重建**；装载前对 `depends_on` 拓扑排序并做**环检测**；卸载按**逆拓扑序**。
- **数据接口**：`register()` / `unregister()` / `route(event_ty) -> &[Subscription]` / `get(id)` / `snapshot_index()`。
- **生命周期钩子**：`init` 建空表与路由索引 → `start` 无副作用（纯数据结构） → `stop` 冻结写入（只读路由） → `destroy` 按逆拓扑序清空、触发各插件 `Drop`。

- **子模块 A1：DependencyGraph（第2层）**
  - 本质：在"注册表维护插件归属"的时空约束下，本子模块的本质是 **保证装载时间流顺序合法（无环）的有向图校验器**。
  - 规范 `Edge{from, to, kind: Hard|Soft}`；存储 `petgraph::DiGraph`；流转 `topo_order()` / `detect_cycle()` / `reverse_topo()`；接口 `add_edge` / `validate` / `order_for_load` / `order_for_unload`。
  - 钩子：`init` 建图 → `destroy` 清图（无独立时间流）。
- **子模块 A2：Router（第2层）**
  - 本质：在"注册表维护插件归属"的时空约束下，本子模块的本质是 **把一条事件时间流扇出到合法订阅者的静态索引**。
  - 规范 `Subscription{plugin_id, event_pattern, priority, filter}`；存储 `HashMap<EventType, Vec<Subscription>>`（按 priority **预排序**，避免每次分发排序）；流转：增量增删 + 稳定排序；接口 `subscribe` / `unsubscribe` / `match(event)`。

### 模块 B：LifecycleManager — 生命周期状态机（`domain/lifecycle`，由 `runtime` 驱动，第1层）

- **本质**：在"内核编排插件的执行时间流"的时空约束下，本模块的本质是 **插件状态在合法迁移路径上的唯一仲裁者，尤其保证热替换时 in-flight 请求被安全 drain**。
- **数据规范**：

```rust
pub enum LifecycleState {
    Unloaded, Loading, Rejected, Loaded,
    Starting, Running, Draining, Stopped,
    Destroying, Failed,
}
```

- **合法迁移**：`Unloaded→Loading→(Loaded | Rejected)`；`Loaded→Starting→(Running | Failed)`；`Running→Draining→Stopped→Destroying→Unloaded`；任意态 `→Failed`（panic / drain 超时 / 契约校验失败）。
- **数据存储**：状态驻留 `Registration.state`（内存）；迁移历史写入 `infrastructure/` 审计日志（可选）。
- **数据流转**：迁移由 `application/hotswap.rs` 用例编排，`runtime` 执行域内实际调用（`load` / `start` / `drain(timeout)` / `destroy`）；每次迁移广播 `PluginLifecycleEvent`（供可观测插件消费）。
- **数据接口**：`transition(id, target) -> Result<(), IllegalTransition>` / `is_draining(id)` / `drain_deadline(id)`。
- **生命周期钩子**：`init` 将所有登记项置 `Unloaded` → `start` 订阅生命周期事件 → `stop` 触发全局 drain → `destroy` 逆序销毁。

- **子模块 B1：DrainCoordinator（第2层）**
  - 本质：在"生命周期状态机保证时间流不撕裂"的时空约束下，本子模块的本质是 **在途请求计数器 + 超时熔断的闸门**。
  - 规范 `InFlight{plugin_id, generation, count, deadline}`；存储：原子计数器；流转：`enter()` / `leave()` / `wait_zero(deadline)`；超时则**强制推进**并标记 `Failed`；接口 `acquire(gen)` / `release(gen)` / `await_drain(gen, timeout)`。

### 模块 C：Scheduler / EventBus — 时间编排（`runtime/scheduler`，第1层）

- **本质**：在"内核编排插件的执行时间流"的时空约束下，本模块的本质是 **事件循环 Loop 的载体与分发器，负责优先级、并发度与背压**。
- **数据规范**：`Envelope{trace_id, event, target, priority, deadline}`、`Priority{Critical, High, Normal, Low}`、`BackpressurePolicy{Reject, Block, DropOldest}`。
- **数据存储**：多泳道有界 `mpsc` 队列（每优先级一条）；**状态类用 `watch`、事件类用 `broadcast`**（B1）；**队列有界是背压的物理前提**。
- **数据流转**：`recv()` 按优先级加权取事件 → 开 `tracing` span 注入 `trace_id` → **一次性快照 `(handle, generation)`（B5）** → 按 `time_semantics` 决定 `Serial`（同插件串行保序，载体是插件级 mailbox）或 `Concurrent`（`Semaphore` permit + `tokio::spawn` + `CancellationToken` + `JoinSet` 回收）→ 调用执行域 → 回收结果/错误 → 插件 panic 由 `catch_unwind` 兜底，**唯一后续动作是上报 `Failed` 并卸载**（B2）。
- **数据接口**：`publish(event)` / `subscribe(pattern)` / `dispatch(env)` / `set_backpressure(policy)`。
- **生命周期钩子**：`init` 建通道与泳道 → `start` 拉起主循环任务（持有 `CancellationToken`）→ `stop` 取消 token、停止收新、等待在途完成 → `destroy` 关闭通道、回收任务句柄。

- **子模块 C1：PriorityLanes（第2层）** — 加权轮转取事件，防低优先级饿死；规范 `Lane{priority, weight, capacity}`；接口 `enqueue` / `dequeue_weighted`。
- **子模块 C2：Backpressure（第2层）** — 水位监控与策略执行；接口 `on_full(policy)`；流转：超限时按策略拒绝 / 阻塞 / 丢弃最旧。

### 模块 D：ExecutionDomain — 多执行域（`runtime/domain`，第1层）

- **本质**：在"内核强制校验插件契约与权限"的时空约束下，本模块的本质是 **L2 线协议在不同隔离强度宿主上的执行器集合——即时空规则的执行者**。
- **关键判定**：执行域适配器属于**内核，不是插件**（程序.md 已确认）。
- **数据规范**：

```rust
#[async_trait]
pub trait ExecutionDomain: Send + Sync {
    fn kind(&self) -> DomainKind;                                    // InProcess|Wasm|Process
    fn load(&self, manifest: &PluginManifest) -> Result<DomainHandle>;
    async fn start(&self, h: &DomainHandle) -> Result<()>;
    async fn dispatch(&self, h: &DomainHandle, env: Envelope) -> Result<Envelope>;
    async fn drain(&self, h: &DomainHandle, timeout: Duration) -> Result<()>;
    async fn destroy(&self, h: DomainHandle) -> Result<()>;           // 空间回收
}
```

- **数据存储**：`DomainTable: HashMap<DomainKind, Arc<dyn ExecutionDomain>>`；进程内域持有 `Arc<dyn Plugin>`；WASM 域持有 `wasmtime::Store` + 实例化组件；进程域持有子进程句柄 + gRPC channel。
- **数据流转**：`dispatch` 前后统一做**契约与门控校验**（`ApiVersion` 匹配、`Capability` 检查）；进程内域包裹 `catch_unwind`（错误边界必须在域内消化，不可跨 FFI unwind）；WASM / 进程域天然隔离，错误经 `Result` 回传。
- **数据接口**：上述 trait 的五个方法 + `kind()`。
- **生命周期钩子**：`init` 注册各域适配器 → `start` 拉起进程域健康检查 / WASM 引擎预热 → `stop` 全域 drain → `destroy` 逆序销毁域内所有句柄。

- **子模块 D1：InProcessDomain（第2层）** — 同语言零开销快车道；句柄恒为 `Arc<dyn Plugin>`（A1，全 `&self`，内核侧零锁），注册表 `ArcSwap` 原子替换；panic 用 `catch_unwind` 隔离，捕获即 `Failed` + 卸载（B2）。
- **子模块 D2：WasmDomain（第2层）** — wasmtime 组件模型 + `kernel.wit`；线性内存天然无跨插件互访、可跨语言、近原生性能。**因 `Store` 不可重入，WASM 域强制 `Serial`**（A3）；时间上限为 `fuel` + `epoch` + `host_timeout` 三重（B3）。
- **子模块 D3：ProcessDomain（第2层）** — gRPC + `kernel.proto`；对语言最宽容（默认决策 **D1 首选**）；崩溃自愈、可独立升级。

### 模块 E：CapabilityGate — 能力门控（`domain/capability`，由 `runtime` 执行，第1层）

- **本质**：在"内核强制校验插件契约与权限"的时空约束下，本模块的本质是 **把"插件能碰哪些外部空间"从运行期约定提升为装载期可判定、调用期可拦截的显式规则**。
- **数据规范**：`Capability` 枚举（`Net:Outbound(host)`、`Fs:Read(path)`、`Fs:Write(path)`、`Env:Read(key)`、`Kernel:Spawn`、`Kernel:Shutdown`、`Bus:Publish(ty)`、`Bus:Subscribe(ty)`…）+ `Grant` / `Deny` 策略；默认 **deny-by-default**。
- **数据存储**：声明来自插件清单（TOML），经 JSON Schema 校验后驻留内存；策略源可来自配置文件或 `infrastructure/`。
- **数据流转**：装载期做**契约校验**（`ApiVersion` semver 兼容 + 清单 Schema + 依赖环检测）；调用期对越界能力直接 `Err(PermissionDenied)` 并发出审计事件。
- **数据接口**：`validate_manifest(m) -> Result<()>` / `check(id, cap) -> Result<()>`。
- **生命周期钩子**：`init` 加载策略 → `start` 订阅越界审计事件 → `stop` 冻结策略变更 → `destroy` 清空策略表。

### 模块 F：HotSwap 用例（`application/hotswap`，第1层）

- **本质**：在"内核支持不停机替换能力"的时空约束下，本模块的本质是 **一次跨模块的事务性编排：新版本上台与旧版本退场必须原子、可回滚、且不撕裂在途时间流**。
- **数据规范**：`HotSwapPlan{plugin_id, from_gen, to_gen, drain_timeout, rollback_on_failure}`、`HotSwapReport{steps, duration, drained, rolled_back}`。
- **数据存储**：无自有存储；编排 `Registry` + `LifecycleManager` + `ExecutionDomain` + `Snapshot` 四者状态。
- **数据流转**（事务时间线，详见 `docs/06-热替换与状态迁移.md`）：

  1. `validate` 新清单（Schema + `ApiVersion` + 能力 + 环检测）
  2. `load` 新插件（新 `Generation`），**旧插件仍 `Running`**
  3. `snapshot` 旧状态（**M1 禁用迁移，恒走"丢弃 + 冷启动"**）→ M4 再启用 `transfer` / `restore`
  4. `start` 新实例
  5. 注册表 **`compare_switch(id, expected=from_gen, new=to_gen)`（CAS）** 原子切换路由（此后新事件只进新实例）
  6. 旧实例转 `Draining`：拒新 + `await_drain(timeout)`；draining 世代的任务豁免背压 `Block`（B4）
  7. `destroy(&self)` 幂等通知 + `Drop` 真正回收空间（A1）
  8. 任一步失败 → `rollback`：`compare_switch(id, expected=to_gen, new=from_gen)` + `destroy(new)`，标记 `Failed`

- **数据接口**：`hotswap(plan) -> Result<HotSwapReport>`。
- **生命周期钩子**：`init` 注入依赖 → `start` 订阅热替换请求事件 → `stop` 拒绝新计划、等待在途计划完成 → `destroy` 释放编排资源。

### 模块 G：Observability — 可观测性（`core` 门面 + `runtime/observability`，第1层）

- **本质**：在"内核承担跨插件 trace 串联"的时空约束下，本模块的本质是 **为所有时间流分配统一的因果标识（`trace_id`），使跨插件、跨执行域的调用链可被完整重建**。
- **数据规范**：`TraceId`（ULID / UUIDv7，时间有序）、`SpanId`、`SpanKind`、`LogLevel`、`MetricKey`。
- **数据存储**：`tracing` Subscriber + span 栈；导出由 `infrastructure/` 实现（OTLP / 文件 / stdout）。
- **数据流转**：事件进入调度器即开 span → 分发至插件时 `trace_id` 随 `Envelope` 透传（进程域经 gRPC metadata、WASM 域经组件调用参数）→ 插件回传后闭合 span。
- **数据接口**：`span_for(trace_id)` / `inject(env)` / `export()`。
- **生命周期钩子**：`init` 装配 Subscriber → `start` 启动导出任务 → `stop` flush 缓冲 → `destroy` 关闭导出器。
- **易漏项提醒**：插件自打日志**无法**完成链路追踪，故此项必须留在内核（程序.md 已确认）。

### 模块 H：Snapshot / Migration（`domain/snapshot` + `infrastructure`，第1层）

- **本质**：在"热替换时旧插件状态可丢弃或可快照迁移"的时空约束下，本模块的本质是 **插件私有空间在换代之间的序列化与移交协议**。
- **数据规范**：

```rust
pub trait Migratable {
    fn snapshot(&self) -> Result<Snapshot>;
    fn restore(&mut self, s: Snapshot) -> Result<()>;
}
pub struct Snapshot { pub plugin_id: PluginId, pub generation: Generation,
                      pub format: SnapshotFormat, pub payload: Bytes }
```

- **数据存储**：内存态由插件自持；落盘 / 上传由 `infrastructure/` 快照后端。
- **数据流转**：`snapshot → 校验 format 版本 → transfer → restore`；未实现 `Migratable` 的插件走"丢弃 + 冷启动"路径。
- **数据接口**：`snapshot(id)` / `restore(id, snap)` / `is_migratable(id)`。
- **生命周期钩子**：`init` 注册后端 → `start` 无 → `stop` 停止接收快照请求 → `destroy` 清理临时快照。

## 验证方式

采用 **P（前置，空间就绪）/ Q（后置，时间流走通）/ I（不变量，规则守住）** 三维验证；若含 LLM 协同产物，额外增加 `validate_llm()`。

### P（前置条件）

| # | 检查项 | 判定标准 |
|---|---|---|
| P1 | `Kernel::init` 返回 Ok，注册表为空但可用 | 路由表可查询且为空 |
| P2 | `KernelConfig` 校验通过（配置完整） | 缺必填字段直接 `Err` |
| P3 | 清单中出现的 `domain` 均有已注册的执行域适配器 | `DomainTable` 覆盖度 = 100% |
| P4 | 快照后端（若启用）连通 | 读探针返回 Ok |

### Q（后置条件）

| # | 检查项 | 判定标准 |
|---|---|---|
| Q1 | 装载后插件进入 `Running` | 状态查询返回 `Running` |
| Q2 | 发布事件后插件 `on_event` 被正确触发 | 断言回调次数与顺序 |
| Q3 | 热替换后**新事件全部**由新 `Generation` 处理 | 处理方 `generation == to_gen` |
| Q4 | 热替换后旧实例 in-flight 请求**全部完成** | `await_drain` 在超时前归零且无丢失计数 |
| Q5 | 进程内插件 panic 后内核存活，其余插件不受影响 | `kernel.is_alive()` 为 true |
| Q6 | 越权调用被拦截 | 返回 `PermissionDenied` 且审计事件已发出 |
| Q7 | 循环依赖被拒绝装载 | `Err(CycleDetected)` |
| Q8 | 插件 `on_event` panic 后**不再接收任何事件** | 断言该插件 `state == Failed` 且后续事件计数增量为 0（B2） |
| Q9 | `domain = "wasm"` + `semantics = "concurrent"` 被拒绝 | `Err(K202)`，且无静默降级（A3） |
| Q10 | drain 期间 in-flight 任务向满泳道 `publish`，热替换**不死锁** | `await_drain` 在超时前归零，任务收到 `K403` 而非无限阻塞（B4） |
| Q11 | 慢消费者不丢依赖状态 | 人为滞后 1s 后仍解析到正确的依赖可用性（B1） |
| Q12 | 并发两次热替换 | 第二次 `compare_switch` 返回 `GenerationMismatch`，最终世代唯一（A4） |

### I（不变量）

| # | 检查项 | 判定标准 |
|---|---|---|
| I1 | 每次 `init` 必有对应 `destroy` | 测试收尾断言"未配对的生命周期计数 == 0" |
| I2 | 插件间无直接内存互访 | 静态检查：插件 crate 的 `Cargo.toml` 仅允许依赖 `sdk`；WASM 域天然保证 |
| I3 | 接口 `ApiVersion` 向后兼容 | 兼容矩阵测试（旧插件在新内核上仍可装载） |
| I4 | 热替换不引发时间流撕裂 | Q4 + 事件丢失计数为 0 |
| I5 | 依赖方向铁律未破 | `xtask layering`：`domain` 不引用 `infrastructure` 具体类型；`xtask deps`：`plugins/*` 仅依赖 `sdk`（**编译期硬禁，不可降级为 lint**） |
| I6 | 内核分发路径无锁 | 静态检查：内核中不存在 `Arc<Mutex<dyn Plugin>>`；句柄恒为 `Arc<dyn Plugin>`（A1） |
| I7 | 无世代泄漏 | `Arc::strong_count(handle) == 1` 且 `inflight_count == 0`（A1 + B5） |
| I8 | L2 契约无类型漂移 | `xtask check-abi` 字段级通过；`Envelope` 中不含 `Instant` / `Arc` / 非 `'static` 借用（A2） |

### 判定逻辑

| P | Q | I | 决策 |
|---|---|---|---|
| ❌ | - | - | 阻断，修复前置 |
| ✅ | ✅ | ✅ | 保留（commit） |
| ✅ | ✅ | ❌ | 回退（规则被破坏） |
| ✅ | ❌ | ✅ | 回退（时间流执行错误） |

## 项目愿景

| 阶段 | 目标 | 关键交付 |
|---|---|---|
| **M1 · 内核骨架（首批）** | 跑通闭环 | `core` + `sdk` + `runtime`（事件循环 + 进程内域）+ `domain`（注册表 / 状态机）+ 2 个示例插件；"装载 → 事件流转 → 热替换 → 卸载"闭环通过 P/Q/I |
| **M2 · 契约外置** | 跨语言打通 | 落地 `schema/`（`kernel.wit` + `plugin-manifest.schema.json`）；`trait Plugin` 降级为 L3 绑定；进程域（gRPC + protobuf）打通，首个非 Rust 插件跑通（默认决策 D1/D2） |
| **M3 · 强隔离** | 不可信插件 | WASM 域接入（wasmtime 组件模型），不可信插件默认走 WASM；能力门控细化到 host/path 级别 |
| **M4 · 状态迁移** | 有状态平滑换代 | `Migratable` 协议 + 快照后端；背压与优先级策略可配置化 |
| **M5 · 生态** | 规模化 | 插件市场清单规范、多语言 SDK 绑定（Rust / Python / TS）、Admin API 与可观测性完备；远期支持跨机插件编排 |

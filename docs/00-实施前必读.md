## 0. 一个前提（决定一切）

本项目的**具体实现由 AI 编码助手（Code Agent）主体完成**。因此：

- 不再为人类"写代码累不累 / 胶水多不多 / 跨 crate 重构痛不痛"优化——AI 不怕这些。
- 优化目标切换为：**降低 AI 看不见逻辑陷阱、盲目照抄导致运行时崩溃的概率**。
- 所有"分层强制""契约一致""测试覆盖"都是为了让 AI 的每一步都有**可机械校验的锚点**。

## 1. 已裁定但需牢记的接口形状（A 组：不改必返工）

这些是**接口契约**，AI 必须照此实现，不得在落地时"灵活化"：

### A1 · `trait Plugin` 全部方法统一 `&self`
- 句柄恒为 `Arc<dyn Plugin>`，**内核侧禁止**出现 `Arc<Mutex<dyn Plugin>>` / `&mut self` / `self: Box<Self>`。
- 插件内部可变性由插件自己承担（`Mutex`/`RwLock`/原子量/actor mailbox）。
- `destroy(&self)` 是幂等通知；真正的空间释放在 `Drop`。
- **为什么**：混用接收者会逼出内核分发路径上的互斥锁 = 死锁 + 串行化双杀。

### A2 · `Envelope.deadline` 是 `Option<Duration>`（相对时长），**不是** `Instant`
- `Instant` 是进程本地单调时钟，跨 ABI / 跨进程无意义；与 wit `deadline-ms` / proto `deadline_ms` 语义漂移。
- 出现在 `Envelope` 中的每个 Rust 类型都必须跨 ABI 可序列化；**禁止 `Instant` / `Arc` / 裸引用 / 非 `'static` 借用**。

### A3 · WASM 域强制 `Serial`
- 装载期：`manifest.domain == "wasm"` 且 `semantics == "concurrent"` ⇒ 直接 `Rejected`（`K202`），**不做静默降级**。
- `Serial` 的载体是**插件级 mailbox（actor）**，不是优先级泳道（泳道跨优先级取事件，无法单插件内保序）。

### A4 · 世代切换用 `compare_switch`（CAS），不用 `switch_generation`
- 签名：`compare_switch(id, expected: Generation, new: Generation) -> Result<(), GenerationMismatch>`。
- 热替换事务开始时把 `from_gen` **快照**进 `HotSwapPlan`，事务内**禁止**再调 `generation(id)` 重新查询。
- 回滚时 `expected` 必须填 `to_gen`（本次计划引入的世代），填错会立刻暴露而不是潜伏。

## 2. 诡异 bug 防火墙（B 组：不改会出编译通过但功能错误的坑）

### B1 · 状态类用 `watch`，事件类用 `broadcast`
- 依赖可用性、生命周期状态、配置 = **状态** ⇒ `watch`（订阅即得当前值 + 可重放）。
- 审计日志、指标 = **事件** ⇒ `broadcast`。
- 依赖解析必须写成"**先订阅 → 再立刻读当前值**"的 reconcile 函数，顺序不可颠倒。

### B2 · `catch_unwind` 分支的唯一合法动作
- 捕获 panic 后**唯一**合法动作 = `LifecycleManager::transition(id, Failed)` 并触发卸载。
- **严禁**仅 `return Err(K501)` 后让插件继续接客（静默数据损坏）。
- `AssertUnwindSafe` 只是对编译器的承诺，不保证共享状态一致。
- `catch_unwind` 拦不住：`abort`、栈溢出、OOM、在别处 `tokio::spawn` 子任务里的 panic（后者须用 `JoinSet` 回收）。

### B2' · Rust async 的第三类失败——被 drop（取消）
- 取消发生在 deadline 到期 / `stop()` 撤 token / 热替换 abort 三处。
- `DrainCoordinator` 只保证"不再接新活"，**不保证被取消的活是干净的**。
- 需要补偿语义的插件自行实现幂等键 / 事务日志；内核只提供注入点。

### B3 · WASM 时间维度三重上限
- `fuel_limit`（指令级，只防纯计算死循环，不计费 host call）+ `epoch_tick`（墙钟兜底）+ `host_timeout`（每个 host call 包 `tokio::time::timeout`）。
- host call 耗时**必须计入插件 `deadline`**。
- `05` 的 `world` 未 import `wasi:sockets` ⇒ "WASM 禁联网"已结构性强制；实现时**不要**在 `WasiCtxBuilder` 上 `inherit_network()`。

### B4 · drain 与背压的循环等待
- `Draining` 世代的任务**豁免 `Block`**，一律退化为 `Reject`（`K403`）。
- `Block` 策略必须带 `deadline`。
- `max_inflight` 用**调度器帧**持有的 `Semaphore` 许可（spawn 前 acquire），不得在 task 内部自行 acquire。

### B5 · 读撕裂与世代快照
- `dispatch` 开始时**一次性快照 `(handle, generation)`**，此后全程禁止二次解析。
- 在途请求跑在旧世代上是**正确且期望**的；任何"刷新到最新世代"的实现都是 bug。

## 3. 实施纪律（C 组：不进设计文档，进此处 + `xtask`）

### C1 · crate 切分：信任边界优先
- `core`（独立，纯类型）/ `sdk`（独立，插件唯一可见依赖）/ `kernel`（单体，内部 `mod` 隔离）/ `plugins/*`（仅依赖 `sdk`）。
- 必须是 **3 个 crate** 而非 2 个：依赖方向 `kernel → sdk → core` 单向链；若 `core` 并进 `kernel` 会循环依赖。
- 分层从编译期强制降级为 `xtask layering` lint 强制；但 `plugins/*` 只依赖 `sdk` 是**信任边界，仍是编译期硬禁（CI 扫描 `Cargo.toml`）**。

### C2 · `Migratable` 默认实现返回错误，不写 `unimplemented!()`
- `sdk` 中 default method 返回 `Err(KernelError::Unsupported)`，`is_migratable()` 默认 `false`。
- **严禁** `unimplemented!()` / `todo!()` / `panic!()` 出现在 SDK 热路径。

### C3 · `xtask check-abi` 升级到字段级
- 比对函数名 + **字段集合（规范化后）+ 类型映射 + 可序列化性 + 错误码双向映射**。
- 已发现一例真实漂移（`Envelope.deadline` 的 `Instant` vs `u64` 相对时长），字段级检查才能抓到。

### C4 · M0 先行件套（开工必做）
- 时间虚拟化：`tokio::time::pause` / `advance`。
- 8 步事务的失败注入钩子（每个步骤都可被测试强制失败，验证 rollback）。
- **`tests/` 目录归人类所有，AI 只读不写**（承载 P/Q/I 断言 + 失败注入）。

## 4. 给 AI 的开工检查清单

1. 改代码前先跑 `cargo build` + `cargo test` 基线，确认 0 错误 0 警告。
2. 每实现一个模块，对照 `01` 的 Q/I 表与 `tests/` 下人类写的断言，确认该模块相关不变量有测试覆盖。
3. 任何涉及"世代 / drain / panic / 跨插件依赖 / 背压"的改动，**先回本文件第 1、2 节**。
4. 提交前跑 `cargo run -p xtask -- check-abi` + `layering` + `deps`，三者全绿。
5. 绝不在 `Arc<dyn Plugin>` 外包 `Mutex`；绝不把 `deadline` 写成 `Instant`；绝不在 WASM 域允许 `concurrent`；绝不在 `catch_unwind` 里只 `return Err`。
